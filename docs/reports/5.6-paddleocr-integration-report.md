# Báo Cáo Tích Hợp PaddleOCR Vào AI Service (Task 5.6)

## 1. Mục tiêu và phạm vi công việc
Task 5.6 bổ sung PaddleOCR làm công cụ nhận diện chữ tùy chọn cho AI Service, bên cạnh động cơ mặc định là RapidOCR (ONNX). Hệ thống chuyển đổi qua lại giữa hai động cơ thông qua biến môi trường `AI_OCR_ENGINE=paddle` mà không làm thay đổi hợp đồng API hiện có (`POST /api/v1/ocr/license-plate`) hay sửa đổi luồng xử lý chính của task 5.4.

Các công việc đã hoàn thành:
- Xây dựng lớp `PaddleOcrEngine` triển khai giao diện `OcrEngine` sẵn có trong `app/services/ocr_service.py`.
- Thiết lập cơ chế nạp mô hình theo nhu cầu (lazy load), cô lập lỗi nạp và lỗi suy luận thành mã lỗi HTTP chuẩn (`503 MODEL_UNAVAILABLE` và `500 OCR_FAILED`).
- Tạo bộ cấu hình môi trường mới trong `app/core/config.py` và cơ chế tiêm phụ thuộc trong `app/api/deps.py`.
- Tách riêng danh sách thư viện vào `ai-service/requirements-paddle.txt`, ghim chính xác phiên bản để tránh xung đột với môi trường mặc định.
- Viết bộ kiểm thử tự động 20 ca kiểm thử trong `tests/test_paddle_ocr_engine.py` và script kiểm tra thực tế `scripts/paddle_smoke_test.py`.
- Chạy thử nghiệm thực tế thành công trên môi trường Windows CPU từ unit test, smoke test đến gọi API qua Web Swagger UI.

## 2. Công nghệ và môi trường sử dụng

### 2.1. Môi trường hệ thống
- Hệ điều hành: Windows 64-bit.
- Thiết bị tính toán: CPU (không dùng GPU).
- Trình thông dịch: Python 3.12.10.
- Web framework: FastAPI 0.115+, Uvicorn, Pydantic 2.x.

### 2.2. Thư viện OCR và thị giác máy tính
- `paddlepaddle==3.1.0`: Nền tảng học sâu PaddlePaddle phiên bản CPU trên Windows.
- `paddleocr==3.1.0`: Thư viện OCR mã nguồn mở của Baidu.
- `paddlex==3.1.4`: Bộ công cụ quản lý và suy luận pipeline của PaddleOCR 3.x.
- `numpy==1.26.4`: Phiên bản NumPy tương thích với wheel Windows của PaddlePaddle 3.1.0.
- `opencv-contrib-python==4.10.0.84`: Thư viện xử lý ảnh do PaddleX kéo theo.

### 2.3. Các mô hình học sâu được sử dụng
Các mô hình được tải tự động và lưu trữ tại thư mục `C:\Users\\.paddlex\official_models`:
1. `PP-LCNet_x1_0_textline_ori`: Mô hình phân loại và nắn hướng dòng chữ (tránh đọc ngược hoặc lệch góc).
2. `PP-OCRv5_server_det`: Mô hình phát hiện vùng chứa văn bản độ chính xác cao.
3. `PP-OCRv5_server_rec`: Mô hình nhận diện ký tự quang học server.

### 2.4. Bản vá tương thích LangChain
Khi cài đặt PaddleOCR 3.1.0 trên Python 3.12, bộ cài kéo `paddlex 3.1.4`. Do PaddleX không đặt chặn trên cho `langchain`, pip sẽ kéo phiên bản `langchain 1.x` mới nhất. Bản 1.x này đã bỏ module `langchain.docstore`, gây ra lỗi vỡ chương trình `ModuleNotFoundError: No module named 'langchain.docstore'` ngay khi gọi `import paddleocr`.

Giải pháp xử lý: Ghim cứng 5 gói LangChain nhánh 0.3.x vào `requirements-paddle.txt`:
- `langchain==0.3.30`
- `langchain-community==0.3.31`
- `langchain-core==0.3.86`
- `langchain-openai==0.3.35`
- `langchain-text-splitters==0.3.11`

## 3. Kiến trúc và mã nguồn thay đổi

### 3.1. Sơ đồ luồng xử lý
```
POST /api/v1/ocr/license-plate
  │
  ├──> deps.py: get_ocr_engine()
  │      ├── Nếu AI_OCR_ENGINE="paddle"   --> Khởi tạo PaddleOcrEngine
  │      └── Mặc định                     --> Khởi tạo RapidOcrEngine
  │
  └──> ocr_service.py: recognize_plate()
         ├── Tiền xử lý ảnh (enhance_for_ocr)
         ├── engine.read(bgr) --> list[OcrLine(text, confidence, box)]
         ├── Chuẩn hóa định dạng biển số Việt Nam (plate_normalizer)
         └── Đóng gói Envelope chuẩn ApiResponse[LicensePlateResult]
```

### 3.2. Chi tiết các tệp thay đổi trong `ai-service/`
- `app/services/paddle_ocr_engine.py` (Mới): Lớp `PaddleOcrEngine` nạp lười mô hình, có khóa tuần tự hóa luồng `threading.Lock()` do PaddleOCR C++ backend không an toàn đa luồng trên Windows. Chuẩn hóa đầu ra `parse_v3()` và `parse_v2()` về kiểu `OcrLine(text, confidence, box)` với hộp trục tọa độ chữ nhật `(x_min, y_min, x_max, y_max)`.
- `app/core/errors.py`: Bổ sung mã lỗi `OcrFailedError` (HTTP 500, code `OCR_FAILED`).
- `app/core/config.py`: Thêm các tham số cấu hình: `ocr_engine`, `paddle_lang`, `paddle_device`, `paddle_det_model`, `paddle_rec_model`, `paddle_retry_cooldown_s`.
- `app/api/deps.py`: Cập nhật hàm `get_ocr_engine()` chuyển hướng linh hoạt theo cấu hình.
- `requirements-paddle.txt`: Định nghĩa các gói phụ thuộc bổ sung cho PaddleOCR.
- `tests/test_paddle_ocr_engine.py` (Mới): 20 ca kiểm thử kiểm tra toàn bộ luồng logic, xử lý ngoại lệ và chuyển đổi dữ liệu.
- `scripts/paddle_smoke_test.py` (Mới): Kịch bản kiểm tra độc lập nhận diện ảnh thực tế ngoài luồng web.

## 4. Hướng dẫn cài đặt và vận hành

### 4.1. Cài đặt môi trường
Từ thư mục gốc dự án:
```powershell
cd ai-service
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install -r requirements-paddle.txt
```

### 4.2. Chạy kiểm thử tự động
1. Chạy 20 ca kiểm thử logic và nạp mô hình:
```powershell
python -m pytest
```
2. Chạy smoke test kiểm tra nhận diện ảnh giả lập:
```powershell
python scripts\paddle_smoke_test.py
```
Kết quả kỳ vọng: Báo `51F-123.45`, `found=True`, `valid=True`.

### 4.3. Khởi chạy Web API và kiểm thử qua trình duyệt
Mở cửa sổ PowerShell và chạy:
```powershell
cd ai-service
.\.venv\Scripts\Activate.ps1

# Bật cờ dùng PaddleOCR và tăng thời gian chờ cho CPU
$env:AI_OCR_ENGINE = "paddle"
$env:AI_REQUEST_TIMEOUT_S = "120"

uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

Sau khi server khởi động:
1. Mở trình duyệt truy cập: `http://127.0.0.1:8000/docs` (Swagger UI).
2. Tìm endpoint `POST /api/v1/ocr/license-plate`.
3. Nhấn **Try it out**, chọn tệp ảnh biển số xe và bấm **Execute**.
4. Kết quả trả về mã HTTP `200` với cấu trúc JSON chuẩn:

## 5. Kết quả kiểm thử thực nghiệm

### 5.1. Thử nghiệm trên các điều kiện ảnh tổng hợp
Thử nghiệm trên 6 ca ảnh đại diện cho các điều kiện quang học thực tế:

| Điều kiện ảnh | Kết quả nhận diện | Đánh giá kỹ thuật |
| :--- | :--- | :--- |
| **Ảnh rõ nét** | Đọc chính xác 100% hai dòng chữ (độ tin cậy 0.93 - 0.99). | Hoạt động tốt trong điều kiện chuẩn. |
| **Ảnh chữ nhỏ** | Nhận diện nhầm `Nguyan` thay cho `Nguyen` (độ tin cậy 0.92). | Có hiện tượng tự tin cao dù sai một ký tự cục bộ. |
| **Ảnh xoay nghiêng 8°** | Đọc đủ nội dung, chia thành 3 đoạn văn bản. | Mô hình hướng chữ `PP-LCNet` nắn góc xoay hiệu quả. |
| **Ảnh làm mờ ($\sigma=3$)** | Đọc được văn bản nhưng bị tách rời từng từ; từ `SO` đạt 0.742. | Giảm nhẹ độ tin cậy khi biên nét mờ. |
| **Ảnh nhiễu hạt ($\sigma=25$)** | Đọc nhầm `S0` (số 0) thay cho `SO` (chữ O) với độ tin cậy 0.95. | Nhầm lẫn giữa chữ O và số 0 trong môi trường nhiễu. |
| **Ảnh nền trắng rỗng** | Trả về danh sách rỗng, không sinh chữ ảo. | Bộ lọc tin cậy hoạt động đúng. |

### 5.2. Đo kiểm hiệu năng và tài nguyên
- **Thời gian xử lý trên CPU:** Dao động từ 15 đến 43 giây cho một request nhận diện biển số hoàn chỉnh (lần đầu nạp mô hình mất khoảng 40 giây).
- **Nguyên nhân thời gian kéo dài:** Bộ mô hình `PP-OCRv5_server` có lượng tham số lớn. Đồng thời pipeline `recognize_plate` thực hiện phân đoạn crop nhiều vùng nghi ngờ kết hợp đọc toàn khung hình, dẫn đến việc gọi mô hình suy luận từ 2 đến 3 lần cho mỗi ảnh.
- **Xác nhận kết quả:** Tất cả các ca kiểm thử `pytest` (20/20 đạt), smoke test và endpoint API thực tế đều hoàn thành chính xác.

## 6. Giới hạn tồn tại và khuyến nghị kỹ thuật

1. **Thời gian phản hồi trên CPU:**
   Do PaddleOCR server chạy trên CPU tương đối chậm, biến môi trường `AI_REQUEST_TIMEOUT_S` bắt buộc phải cấu hình từ `60` đến `120` giây (mặc định của hệ thống là `20` giây sẽ gây lỗi HTTP 504 Timeout). Với các nghiệp vụ cần phản hồi tức thì (dưới 1 giây), nên giữ động cơ mặc định là RapidOCR.
2. **Xung đột DLL với PyTorch trên Windows:**
   Thực nghiệm cho thấy nếu tiến trình gọi `import paddle` trước rồi gọi `import torch` (thư viện của YOLO detector) trên cùng môi trường Windows, sẽ xảy ra lỗi xung đột thư viện liên kết động C++ runtime (`shm.dll`). Để tránh lỗi này khi khởi động server, cờ nạp trước mô hình cần đặt `$env:AI_PRELOAD_MODELS="false"` hoặc duy trì môi trường chạy riêng biệt.
3. **Cảnh báo phụ thuộc từ `pip check`:**
   Môi trường xuất hiện cảnh báo metadata về việc `opencv-python` yêu cầu `numpy>=2.0` trong khi PaddlePaddle ghim `numpy==1.26.4`. Thực tế runtime đang sử dụng gói `opencv-contrib-python 4.10.0.84` tương thích hoàn toàn với NumPy 1.26.4 nên cảnh báo này không ảnh hưởng đến hoạt động của hệ thống.
