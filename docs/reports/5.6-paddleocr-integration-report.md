# 5.6 Báo Cáo Tích Hợp PaddleOCR Vào AI Service

> Phiên bản này **thay thế** báo cáo 5.6 trước đó. Bản trước viết cho một service độc lập do nhầm hợp đồng; nay PaddleOCR được cắm vào AI Service 5.4 hiện có.

## 0. Quy ước trạng thái

| Ký hiệu | Ý nghĩa |
| :--- | :--- |
| ✅ | Đã chạy thật, có kết quả ghi nhận |
| 🟡 | Đã viết, chưa chạy trong điều kiện thật (nêu rõ lý do) |
| ⚪ | Chỉ là đề xuất |

> [!IMPORTANT]
> **Bản ghép vào 5.4 chưa được chạy với PaddleOCR thật.** Bằng chứng PaddleOCR chạy thật (mục 7.1) đến từ lần chạy trước trên Windows với **mã độc lập cũ**, không phải mã đã ghép. Cần chạy `scripts/paddle_smoke_test.py` và gọi API thật (mục 9) trước khi coi task hoàn tất.

## 1. Tổng quan và mục tiêu
AI Service 5.4 đã có OCR biển số bằng RapidOCR (`OcrEngine`, `recognize_plate`, chuẩn hóa biển số VN, envelope `ApiResponse`, timeout, semaphore). Task 5.6: tích hợp PaddleOCR **mà không đổi kiến trúc hay hợp đồng API**. Giải pháp: thêm `PaddleOcrEngine` cùng giao diện `OcrEngine`, chọn bằng cấu hình `AI_OCR_ENGINE=paddle`; mặc định vẫn là RapidOCR. Không làm Face/AI Matching, backend, frontend, DB.

## 2. Môi trường và phiên bản
- Python **3.12.10**, Windows 64-bit, CPU (chuẩn của nhóm).
- Bộ phiên bản Paddle (`requirements-paddle.txt`): `paddlepaddle==3.1.0`, `paddleocr==3.1.0`, `paddlex==3.1.4`, `numpy==1.26.4`.
- ✅ Bộ này cài và chạy được trên máy Windows của nhóm khi dùng riêng (xem 7.1): `pip check` sạch, `import paddle/paddleocr`, `paddle.utils.run_check()` đạt.
- 🟡 **Chưa thử cùng `requirements.txt` của 5.4** (ultralytics/torch, rapidocr, onnxruntime, opencv-python-headless) trong một venv. Rủi ro đã biết: nhiều gói OpenCV đè nhau; xung đột DLL giữa torch và paddle trên Windows (chưa kiểm chứng). Khuyến nghị thử trong venv riêng.
- Vì sao ghim như vậy (đã gặp thật): `paddleocr 3.0.0` → `paddlex 3.0.0` ghim `pandas<=1.5.3`, không có wheel cho Python 3.12 → build lỗi `pkg_resources`; `paddleocr 3.1.0` không chặn trên nên pip lấy `paddlex 3.7.2` và `PaddleOCR(...)` lỗi `PaddlePredictorOption.__init__() takes 1 positional argument but 2 were given`; ghim `paddlex==3.1.4` khắc phục (ghi nhận ở 7.1).

## 4. Kiến trúc và luồng
```
POST /api/v1/ocr/license-plate   (không đổi)
  -> recognize_plate()            định vị -> enhance_for_ocr -> engine.read -> chuẩn hóa -> xếp hạng (không đổi)
       engine = get_ocr_engine()  AI_OCR_ENGINE: rapidocr (mặc định) | paddle
                  └─ PaddleOcrEngine.read(bgr) -> list[OcrLine(text, confidence, box xyxy)]
```
- `import` module không kéo `paddle` và không chạm mạng (có test chạy tiến trình con để kiểm).
- Nạp thất bại (thiếu thư viện, không tải được mô hình, sai tham số) → `ModelUnavailableError` (503 `MODEL_UNAVAILABLE`); sau lỗi chờ `paddle_retry_cooldown_s` (30 giây) mới thử lại. Preload khi khởi động (`AI_PRELOAD_MODELS`) lỗi chỉ ghi log.
- Suy luận lỗi → `OcrFailedError` (500 `OCR_FAILED`), thông báo không lộ chi tiết nội bộ; log chỉ ghi tên kiểu lỗi, không ghi văn bản nhận dạng.
- PaddleOCR không đảm bảo an toàn luồng → khóa tuần tự hóa suy luận.
- Không tự tạo dữ liệu: dòng nào PaddleOCR không trả đủ văn bản + confidence + đa giác thì bị bỏ. Đa giác được đổi sang hộp trục `xyxy` (min/max) vì `OcrLine` của 5.4 dùng hộp trục; toạ độ gốc do pipeline 5.4 quy về ảnh gốc như cũ.
- Tiền xử lý dùng nguyên `enhance_for_ocr` của 5.4. Bộ tiền xử lý có điều kiện (nắn nghiêng, khử nhiễu…) của bản độc lập cũ **không mang sang**.

## 5. Định dạng đầu ra
Dùng nguyên `ApiResponse[LicensePlateResult]` của 5.4 (`raw_text`, `plate`, `confidence`, `box`, `candidates`…). Không thêm định dạng mới. Confidence và box chỉ lấy từ PaddleOCR.

## 6. Cấu hình
`AI_OCR_ENGINE` (rapidocr|paddle), `AI_PADDLE_LANG` (en), `AI_PADDLE_DEVICE` (cpu), `AI_PADDLE_DET_MODEL` / `AI_PADDLE_REC_MODEL` (mặc định trống; ví dụ model `mobile` — 🟡 chưa thử), `AI_PADDLE_RETRY_COOLDOWN_S` (30).
**Quan trọng:** PaddleOCR trên CPU chậm (7.1: 10–22 giây/ảnh 640×200), mà mặc định `AI_REQUEST_TIMEOUT_S=20` và pipeline biển số có thể gọi engine nhiều lần → nên đặt `AI_REQUEST_TIMEOUT_S=120` khi dùng paddle, nếu không có thể gặp 504.

## 7. Kết quả kiểm thử

### 7.1 ✅ PaddleOCR chạy thật trên Windows (mã độc lập cũ, **không phải bản ghép**)
Python 3.12.10, CPU, paddlepaddle 3.1.0, paddleocr 3.1.0, paddlex 3.1.4 (đã ghim): `pip check` sạch; import `paddle`, `paddleocr` đạt; `paddle.utils.run_check()` đạt; mô hình `PP-OCRv5_server_det/rec`, `PP-LCNet_x1_0_textline_ori` tải được; 6 ảnh tổng hợp ASCII:

| Ca | Kết quả |
| :--- | :--- |
| Rõ nét | ✅ đúng cả hai dòng (0.93 / 0.99) |
| Chữ nhỏ | ⚠️ `Nguyan` thay `Nguyen` (0.92) — sai ký tự dù confidence cao |
| Xoay 8° | ✅ đủ nội dung, tách thành 3 đoạn |
| Mờ σ=3 | ✅ đúng nhưng tách từng từ; `SO` 0.742 |
| Nhiễu σ=25 | ⚠️ `S0` (số 0) thay `SO` (0.95) — nhầm O/0 |
| Ảnh trắng | ✅ không sinh chữ ảo |

Thời gian 10–22 giây/ảnh trên CPU (ảnh đầu 39,8 giây gồm nạp mô hình). Đây chỉ là 6 mẫu tổng hợp: **không đủ kết luận tỉ lệ đúng**.

### 7.2 Test của bản ghép (`tests/test_paddle_ocr_engine.py`, 20 test)
- ✅ Chạy thật trong sandbox (Linux, Python 3.12.3, không có pydantic): **12 đạt**, gồm phân tích đầu ra 2.x/3.x, tham số khởi tạo theo phiên bản, thiếu thư viện, lỗi khởi tạo giống lỗi thật `PaddlePredictorOption`, cooldown, import không kéo paddle. Dùng module `paddleocr` **giả**; dữ liệu mẫu dựng theo tài liệu.
- 🟡 **8 test bị bỏ qua** vì sandbox không có pydantic/fastapi: chuyển đổi sang `OcrLine`, bỏ dòng thiếu dữ liệu, lỗi suy luận → `OcrFailedError`, ảnh đầu vào không bị sửa, `recognize_plate` + `PaddleOcrEngine`, chọn engine theo cấu hình. Đã chạy **một lần với shim pydantic/fastapi tạm** (ngoài gói bàn giao): 20/20 đạt. Shim không phải pydantic thật nên **cần chạy `python -m pytest` trên máy nhóm**.
- 🟡 Chưa chạy: toàn bộ test khác của 5.4 với thay đổi `config.py`/`deps.py` (không có trong gói nhận được), API thật qua `uvicorn` với `AI_OCR_ENGINE=paddle`, ảnh biển số thật, tiếng Việt có dấu, hiệu năng/đồng thời, GPU.

## 8. Giới hạn và vấn đề tồn tại
- Chưa kiểm tra bản ghép với PaddleOCR thật; chưa thử chung venv với ultralytics/torch.
- Sai ký tự với confidence cao (e→a, O→0); với biển số, `plate_normalizer` của 5.4 sửa nhầm lẫn O/0 theo vị trí nhưng hiệu quả với kết quả PaddleOCR chưa đo. Kết quả luôn cần người xác minh.
- Chậm trên CPU; pipeline có thể gọi engine nhiều lần (mỗi vùng định vị cộng một lần toàn ảnh) → cần tăng timeout; slot `max_concurrent_jobs` và khóa suy luận khiến yêu cầu xếp hàng.
- Hộp chỉ là hình chữ nhật trục (mất đa giác xoay).
- `lifespan` của 5.4 preload OCR rồi detector trong cùng `try`: nếu preload PaddleOCR lỗi thì bỏ qua preload detector (không sửa `main.py`).
- Tên tham số khởi tạo PaddleOCR 3.x, `text_detection_model_name`/`text_recognition_model_name` — 🟡 phần model tùy chọn chưa chạy thật.
- Ngôn ngữ `en`; tiếng Việt có dấu chưa thử.
- ⚪ Đề xuất: model `mobile` để nhanh hơn; kiểm thử với bộ ảnh biển số thật; đo tỉ lệ đúng giữa RapidOCR và PaddleOCR trên cùng bộ ảnh trước khi chọn engine mặc định.

## 9. Hướng dẫn cài đặt và kiểm thử (Windows PowerShell)
```powershell
cd ai-service
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install -r requirements-paddle.txt
pip check
python -m pytest                          # xem số test đạt/bỏ qua
python scripts\paddle_smoke_test.py       # OCR thật qua engine + recognize_plate (lần đầu tải mô hình)
$env:AI_OCR_ENGINE = "paddle"
$env:AI_REQUEST_TIMEOUT_S = "120"
uvicorn main:app --host 127.0.0.1 --port 8000
```
Cửa sổ khác: `Invoke-RestMethod http://127.0.0.1:8000/health`, mở `/docs`, rồi `curl.exe -F "file=@bien_so.jpg" http://127.0.0.1:8000/api/v1/ocr/license-plate`. Quay lại RapidOCR: bỏ `AI_OCR_ENGINE`.
Nếu import `cv2` lỗi do nhiều gói OpenCV: `pip uninstall -y opencv-python opencv-python-headless opencv-contrib-python` rồi `pip install opencv-contrib-python==4.10.0.84`.
